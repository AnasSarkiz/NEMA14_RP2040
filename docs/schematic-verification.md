# RP2040 schematic verification — v1.8.2

Five functional A4 sheets replace the former per-component pages: Power & USB-PD; Programming & USB; Controller & clocks; Stepper motor driver; Temperature & feedback. Local circuits use real orthogonal wires. Power rails and named interfaces link sheets. Unused physical pins have explicit NC crosses. Same-net branches have junction dots; different-net transverse crossings use native bridge marks. Resistors, capacitors, crystal, diodes and transistor pins use electrical symbols with preserved physical pin identities; the RGB symbol shows three dies in one common-anode package.

The structure follows Rishabh’s [RP2040 reference](https://tscircuit.com/imrishabh18/rp2040-motor-controller#schematic). The reference was inspected as Circuit JSON and rendered, rather than copied from its screenshot. The electrical design remains specific to this controller.

Native `tsci check schematic-placement` reports **zero issues**. The independent [analysis](../artifacts/schematic-redesign/analysis.json) checks **88 source components, 321 physical pins (319 drawn electrical pins and two omitted NC JST hold-down pads), 63 connected source nets and 33 explicitly unused pins**. It verifies conductor geometry and label anchors, complete geometric connectivity through named labels, no different-net wire contacts or overlaps, explicit crossings/junctions, physical pin coverage and A4 bounds. All five native renderings were visually reviewed for readable symbols, values, notes and functional grouping. [Vector PDF](../artifacts/schematic-a4.pdf).

The [preservation receipt](../artifacts/schematic-redesign/preservation.json) records the original v1.6.0 schematic-only change and is historical. Later resistor moves, top-side assembly conversion, separate test pads, SMT JST-SH and native standard USB-C symbols intentionally changed placement and schematic records. The current [functional preservation receipt](../artifacts/top-assembly/functional-preservation.json) compares functional terminals and nets with semantic mapping for the replaced debug pads and USB aliases. No byte-for-byte schematic/source preservation from v1.6.0 is claimed for v1.8.2.

The full board qualification is recorded in [current verification](mounting-usb-verification.md). The corrected order package passes assembly BOM/CPL, paste/stencil and silkscreen CAM checks; the raw exporter retains those findings. Supplier pickup/process acceptance, electrical-layout qualification, hardware/firmware/bench validation and rear motor compatibility remain unverified. Passing schematic analysis is not evidence that assembled hardware has been tested.
